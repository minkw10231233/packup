# PackUp

원룸 · 투룸 · 반포장 이사를 위한 React 기반 이사 서비스 웹앱입니다.  
서비스 소개, 예상 견적 계산, 상담 신청, 관리자용 상담 관리 기능까지 하나의 흐름으로 구성했습니다.

- Demo: https://packup-delta.vercel.app/

## 프로젝트 소개

PackUp은 이사 서비스를 찾는 사용자가 서비스 유형을 확인하고, 조건에 따른 예상 견적을 계산한 뒤 상담 신청까지 진행할 수 있는 웹앱입니다.

초기에는 이사 서비스 소개 중심의 랜딩페이지에 가까운 구조였지만, 서비스 상세 페이지를 데이터 기반으로 분리하고, 예상 견적 계산 기능과 상담 신청 저장 기능, 관리자 페이지를 추가하여 실제 서비스 흐름에 가까운 형태로 개선했습니다.

사용자는 메인 페이지에서 서비스 유형을 확인하고, 예상 견적을 계산한 뒤 상담 신청을 할 수 있습니다.  
관리자 데모 페이지에서는 저장된 상담 신청 데이터를 조회하고, 검색하거나 상태를 변경할 수 있습니다.

## 주요 기능

### 1. 서비스 상세 페이지 데이터 기반 렌더링

- `/service/:id` 라우트를 활용한 동적 상세 페이지 구현
- 운전만, 1인 도움, 2인 도움 서비스를 각각 별도 페이지로 만들지 않고 데이터만 바꿔 렌더링
- 서비스 상세 콘텐츠와 이미지 정보를 `serviceDetails` 데이터로 분리
- 잘못된 서비스 주소 접근 시 예외 화면 제공
- 기존 `/only-drive`, `/one-help`, `/two-help` 주소는 새 상세 페이지 주소로 리다이렉트 처리

### 2. 예상 견적 계산 기능

- 이사 유형, 이동 거리, 층수, 엘리베이터 여부, 짐 양을 입력받아 예상 견적 계산
- 기본 요금, 거리 추가 요금, 층수 추가 요금, 엘리베이터 추가 요금, 짐 양 추가 요금을 분리해 상세 내역 표시
- 입력값 변경 시 계산 결과가 즉시 반영되도록 구현
- 계산 결과 화면에서 상담 신청 페이지로 이동 가능

### 3. 상담 신청 기능

- 이름, 연락처, 이메일, 상담 유형, 희망 날짜, 희망 시간, 상담 내용을 입력받는 상담 신청 폼 구현
- 필수 입력값 검증
- 연락처 형식 검증
- 이메일 형식 검증
- 개인정보 수집 동의 체크 검증
- 상담 신청 완료 시 완료 페이지로 이동

### 4. 상담 신청 데이터 저장

- 상담 신청 데이터를 브라우저 `localStorage`에 저장
- 저장 key: `packup_consults`
- 저장 시 고유 ID와 신청 상태값을 함께 저장
- 기본 상태값은 `pending`으로 설정

> 이 프로젝트의 관리자 페이지는 포트폴리오 데모용이며, 실제 백엔드 서버 대신 브라우저 `localStorage`를 사용했습니다.

### 5. 관리자 페이지

- 관리자 페이지 주소: `/admin`
- 전체 / 대기 / 진행중 / 완료 상담 신청 수 확인
- 이름, 연락처, 이메일, 상담 유형, 상담 내용 기반 검색
- 상태별 필터링
- 상담 상태 변경
- 상담 상세 모달 확인
- 상담 신청 내역 삭제
- ESC 키로 상세 모달 닫기

### 6. 푸터 정책 안내 모달

- 개인정보처리방침
- 이메일 수집 거부
- 취소 및 환불규정

푸터의 정책 버튼 클릭 시 별도 페이지 이동 대신 안내 모달이 열리도록 구현했습니다.  
모달은 외부 영역 클릭 또는 ESC 키로 닫을 수 있습니다.

### 7. 반응형 UI

- 홈 화면
- 서비스 상세 페이지
- 견적 계산 페이지
- 상담 신청 페이지
- 관리자 페이지
- 푸터 모달
- 모바일 메뉴

각 주요 화면에 반응형 스타일을 적용하여 다양한 화면 크기에서 사용할 수 있도록 구성했습니다.

## 주요 구현 내용

### 서비스 상세 페이지 리팩토링

기존에는 서비스 상세 페이지를 각각 별도 컴포넌트로 만들 수 있는 구조였지만, 반복되는 레이아웃이 많기 때문에 하나의 `ServiceDetail` 컴포넌트로 통합했습니다.

서비스별 제목, 본문, 리스트, 이미지 정보는 `serviceDetails` 데이터로 분리했고, URL의 `id` 값에 따라 해당 데이터를 찾아 렌더링하도록 구현했습니다.

이 구조를 통해 새로운 서비스가 추가되어도 페이지 컴포넌트를 새로 만들 필요 없이 데이터만 추가하면 됩니다.

### 견적 계산 로직

견적 계산 페이지에서는 사용자가 선택한 조건에 따라 예상 금액을 계산합니다.

계산에 반영되는 항목은 다음과 같습니다.

- 이사 유형별 기본 요금
- 이동 거리
- 출발지 층수
- 엘리베이터 여부
- 짐 양

계산 결과는 총 금액뿐 아니라 항목별 상세 내역으로도 표시되도록 구성했습니다.

### 상담 신청 및 관리자 페이지

상담 신청 폼에서 사용자가 입력한 데이터는 `localStorage`에 저장됩니다.  
저장된 상담 데이터는 `/admin` 페이지에서 확인할 수 있습니다.

관리자 페이지에서는 상담 신청 목록을 확인하고, 검색하거나 상태별로 필터링할 수 있습니다.  
또한 각 상담의 상태를 대기, 진행중, 완료로 변경할 수 있고, 상세 모달에서 상담 내용을 확인할 수 있습니다.

## 트러블슈팅 및 개선 과정

### 1. 상세 페이지 중복 구조 개선

서비스별 상세 페이지가 반복되는 구조를 데이터 기반 렌더링으로 개선했습니다.  
이를 통해 코드 중복을 줄이고, 서비스 추가 및 수정이 쉬운 구조로 변경했습니다.

### 2. 단순 랜딩페이지 한계 보완

초기 프로젝트는 서비스 소개 중심의 랜딩페이지에 가까웠습니다.  
견적 계산 기능과 상담 신청 저장 기능, 관리자 페이지를 추가하여 실제 사용 흐름이 있는 웹앱 형태로 개선했습니다.

### 3. CSS 충돌 방지

여러 페이지에서 공통 클래스명이 충돌할 수 있어, 홈 화면의 주요 레이아웃 클래스는 `.home-page` 범위 안에서 동작하도록 정리했습니다.

상담 신청 페이지의 `input`, `select`, `textarea` 스타일도 `.consult-page` 내부로 범위를 제한하여 다른 페이지에 영향을 주지 않도록 했습니다.

### 4. 푸터 버튼 기능 개선

기존에는 푸터의 정책 관련 버튼이 실제 기능 없이 존재할 수 있었기 때문에, 클릭 시 안내 모달을 띄우도록 개선했습니다.

이를 통해 UI 요소가 장식에 그치지 않고 실제 동작을 가지도록 만들었습니다.

### 5. GitHub 및 배포 흐름 정리

GitHub Desktop을 사용하여 로컬 프로젝트를 GitHub 저장소와 연결하고, 변경 사항을 커밋 및 푸시하는 방식으로 관리했습니다.

또한 `npm run build`를 통해 배포 가능한 상태를 확인한 뒤 Vercel에 배포했습니다.

## 현재 한계

- 포트폴리오 데모 환경을 위해 실제 백엔드 서버 대신 localStorage를 사용했습니다.
- 관리자 페이지는 인증 기능이 없는 데모용 페이지입니다.
- localStorage 기반이기 때문에 브라우저 또는 기기 간 데이터 공유는 지원하지 않습니다.
- 현재는 React 기반 SPA로 구현되어 있으며, TypeScript와 Next.js는 향후 개선 계획에 포함했습니다.
- 실제 결제나 예약 확정 기능은 포함되어 있지 않습니다.
